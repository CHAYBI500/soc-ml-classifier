Couverture MITRE ATT&CK (tactiques observées)

Tactique observée dans le flux affiché Non observée Lien = tactiques co-observées sur un même agent
À quoi servent les traits entre les nœuds ? Ce ne sont pas des relations officielles du référentiel MITRE : un trait relie deux tactiques observées pour le même agent Wazuh dans la fenêtre d'alertes affichée. Plus il est épais, plus ces deux tactiques apparaissent ensemble souvent. Ça permet de repérer en un coup d'œil une chaîne d'attaque en cours sur un agent (ex. Initial Access → Execution → Command and Control) plutôt que des alertes isolées et sans lien entre elles, et donc de prioriser un agent qui progresse sur plusieurs étapes ATT&CK au lieu d'un agent simplement bruyant sur une seule tactique répétée.
En attente de champs MITRE (rule_mitre_tactic) dans les alertes reçues.

Score d'hygiène calculé côté ce dashboard (pas un score officiel Wazuh), combinant deux familles de signaux. Heuristique locale : -10 pts par port sensible exposé en écoute (RDP, SMB, bases de données…), -5 pts par port supplémentaire au-delà de 5, -15 pts si agent Windows sans correctif recensé, -25 pts si l'OS est en fin de support connue (Windows 7/2008/2012, CentOS 6/7/8…). CVE réelles (si le module Vulnerability Detector Wazuh est actif côté manager) : -8 pts par CVE critique, -4 par CVE haute, -1 par CVE moyenne (plafonds par catégorie). Le détail de chaque faille est listé dans les onglets "Vulnérabilités" et "CVE (Wazuh)" du détail agent (cliquer une ligne du tableau). Nécessite WAZUH_API_HOST/PORT/USER/PASSWORD configurés côté API (accès à l'API REST du manager Wazuh, port 55000 par défaut) ; le module Vulnerability Detector est optionnel — son absence bascule silencieusement sur l'heuristique locale seule.
